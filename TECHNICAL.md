# Техническая документация ПАО "НБД-Банк" (AfinaZ)

## 1. Архитектура
Система состоит из трех основных контейнеров:
1. **app** (Spring Boot) — бизнес-логика, шифрование, генерация PDF.
2. **postgres** (PostgreSQL 15) — хранение метаданных и зашифрованных PII.
3. **angie** (Nginx-совместимый) — reverse-proxy, TLS-терминация (Let's Encrypt / Custom).

## 2. Модель безопасности
* **Файлы документов** шифруются на диске алгоритмом AES-256-GCM (`file.key`).
* **Персональные данные** (email, телефон, ФИО) в БД шифруются AES-256-GCM (`pii.key`).
* **Пароли и токены** не хранятся в открытом виде (используются хэши SHA-256).
* **Подписи** проверяются через BouncyCastle с ручным построением цепочки сертификатов и проверкой CRL.
* **Бэкапы** шифруются AES-256-CBC (`backup.pass`).

## 3. Ключевые компоненты
* `SignatureVerifier` — проверка CAdES-BES, chain building, soft-fail при отсутствии CRL.
* `SignatureVisualizationService` — наложение штампов на PDF (только последняя страница) и футера с логотипом банка (все страницы).
* `CrlDownloader` — автоматическая загрузка CRL по CDP-URL из сертификатов.
* `CleanupService` — очистка дискового пространства (docker-кэш, логи, старые бэкапы, сироты).

## 4. Основные эндпоинты (API)
* `GET /login` — вход клиента (magic-link).
* `POST /api/sign/accept` — подписание документа клиентом.
* `GET /admin/challenge` + `POST /admin/cert-login` — вход админа по УКЭП.
* `POST /admin/documents/{id}/apply-poa` — применение доверенности к подписи.
* `GET /admin/documents/{id}/visualization` — скачивание PDF со штампами.

## 5. Обслуживание
* **Бэкап:** ежедневно в 3:00 через cron (`backup-prod.sh`).
* **Очистка мусора:** `/admin/system` → кнопка «Очистить всё» (Docker, логи, APT, CRL, сироты).
* **Ротация логов:** настроена в `docker-compose-prod.yml` (`max-size: 10m`).

## 6. Схема БД (миграции Flyway)
* `V1-V14` — базовая схема (users, documents, signatures, audit).
* `V15-V19` — папки, доверенности (POA), визуализации.
* `V20-V21` — настройки очистки мусора.
