# ПАО «НБД-Банк» — Сервис подписания документов УКЭП

Веб-сервис для подписания документов усиленной квалифицированной электронной подписью (УКЭП) через плагин КриптоПро. Разработан с учетом требований ФСТЭК и стандартов информационной безопасности банковского сектора.

---

## 1. Требования к серверу

Перед началом развертывания убедитесь, что сервер соответствует требованиям:
* **ОС:** Astra Linux SE 1.8 (рекомендуется для прода) или Ubuntu 22.04/24.04 (для тестов).
* **Архитектура:** x86_64 (ARM не поддерживается из-за КриптоПро).
* **CPU:** 2 vCPU (минимум).
* **RAM:** 4 ГБ (минимум).
* **Диск:** 50 ГБ SSD.
* **Сеть:** Внешний IP-адрес, открытые порты **80** (для проверки домена и редиректа) и **443** (HTTPS).
* **Доступ:** Права `root` или `sudo`.

---

## 2. Что подготовить перед запуском

До начала установки скопируйте в папку с проектом (в корень, где лежит `install.sh`) следующие файлы:

1. **`admins.env`** — файл со списком администраторов. Формат: `ФИО|СНИЛС` (по одному на строку).
   ```text
   Иванов Иван Иванович|12345678901
   ```
2. **`cryptopro-dist/`** — папка с дистрибутивом КриптоПро CSP (файл `linux-amd64_deb.tgz`).
3. **`axiom-dist/`** — папка с дистрибутивом Axiom JDK (файл `axiomjdk-jdk-pro17...tar.gz`).
4. **`certs/`** — папка с корневыми сертификатами УЦ банка (файлы `.cer` или `.crt`).
   *(Если сертификатов нет, скрипт создаст самоподписанный сертификат для тестов).*

## 3. Пошаговая инструкция по развертыванию

### Шаг 3.1. Копирование файлов на сервер
С локальной машины (где лежит проект) выполните команду для копирования файлов на сервер (замените `<IP>` на IP-адрес вашего сервера):
```bash
rsync -avz --exclude '.git' --exclude 'target' --exclude '.idea' --exclude 'secrets' --exclude '.env.prod' --exclude 'backups' -e ssh ./ root@<IP>:/opt/afinaz/
```

### Шаг 3.2. Запуск установщика
Зайдите на сервер по SSH:
```bash
ssh root@<IP>
cd /opt/afinaz
chmod +x *.sh
./install.sh
```

### Шаг 3.3. Ответы на вопросы установщика
Скрипт запустит интерактивное меню. Отвечайте на вопросы:
1. **Домен или IP:** Введите ваш домен (например, `afina.bank.ru`) или IP-адрес, если домена нет.
2. **TLS:**
    * Выберите `1` (Let's Encrypt), если у вас есть домен.
    * Выберите `2` (Свой сертификат), если используете IP или банковский сертификат. Скрипт сам сгенерирует тестовый сертификат, если не найдет ваш.
3. **IP-подсети админов:** Укажите IP-адреса, с которых разрешен доступ в админку (например, `127.0.0.1,192.168.1.0/24`). Для тестов можно ввести `*`.
4. **Режим email:** `log` (письма пишутся в лог) или `smtp` (реальная отправка).
5. **Режим установки:** `1` (Online — соберет образы из исходников, нужен интернет).

> **Важно:** Установщик автоматически:
> - Освободит порты 80 и 443 (остановит Nginx/Apache, если они заняты).
> - Установит Docker и Docker Compose (если их нет).
> - Сгенерирует ключи шифрования (`file.key`, `pii.key`, `backup.pass`) и пароли к БД.
> - Соберет Docker-образы.
> - Запустит контейнеры и проведет 11 автоматических тестов.

### Шаг 3.4. Сохранение учетных данных
В конце установки скрипт создаст файл `install-credentials-*.txt`. В нем лежат пароли от базы данных.
**Обязательно:** Сохраните этот файл в менеджер паролей (1Password, KeePass) и **удалите его с сервера** командой `shred -u install-credentials-*.txt`.

## 4. Доступ к сервису

После успешной установки сервис будет доступен по адресам:
* **Личный кабинет клиента:** `https://<ваш-домен-или-IP>/login`
* **Панель администратора:** `https://<ваш-домен-или-IP>/admin/login`

*(Если вы используете самоподписанный сертификат, браузер выдаст предупреждение безопасности. Нажмите «Дополнительно» -> «Перейти на сайт»).*

---

## 5. Управление сервисом (Меню `afina`)

Для удобства администрирования установщик создает утилиту `afina`. Просто введите её в терминале на сервере:
```bash
afina
```
Откроется интерактивное меню:
1. **Деплой** — обновление кода (git pull + пересборка).
2. **Перезапуск** — быстрый рестарт без пересборки.
3. **Health check** — проверка статуса.
4. **Логи** — просмотр последних 50 строк.
5. **Бэкап** — создание резервной копии БД и файлов.
6. **Восстановление** — накат из бэкапа.
7. **Очистка** — удаление мусора (кэш Docker, старые CRL).
8. **Консоль приложения** (shell).
9. **Консоль базы данных** (psql).

---

## 6. Резервное копирование

Бэкапы создаются автоматически каждый день в 3:00 ночи и шифруются (AES-256-CBC).
Пароль от бэкапа хранится в `secrets/backup.pass`.
Выгрузка бэкапов и ручное управление доступны через меню `afina`.

## 7. Решение проблем (Troubleshooting)

**Ошибка: Порт 80/443 занят**
Установщик должен был решить это сам. Если порт занят вручную, остановите службы:
```bash
systemctl stop nginx apache2 ihttpd
systemctl disable nginx apache2 ihttpd
```

**Ошибка: No such algorithm GOST3411-2012 (при подписи)**
Проверьте, что в контейнере зарегистрирован JCSP. В логах должно быть: `CryptoPro JCSP provider registered: JCSP`.

**Как проверить здоровье сервиса?**
Выполните в терминале сервера:
```bash
curl -sk https://<ваш-домен-или-IP>/actuator/health
```
Ответ должен быть: `{"status":"UP"}`.
