
# ПАО «НБД-Банк» — Сервис подписания документов УКЭП

Веб-сервис для подписания документов усиленной квалифицированной электронной подписью (УКЭП) через плагин КриптоПро. Система разработана с учетом требований информационной безопасности банковского сектора и использует только сертифицированные ФСТЭК России компоненты.

---

## Сертификация и безопасность

Сервис развертывается в защищенном контуре на базе сертифицированных программных продуктов:
* **Операционная система:** Astra Linux Special Edition 1.8 «Смоленск» (Сертификат ФСТЭК № 2557).
* **СУБД:** PostgreSQL 15 в составе Astra Linux (сертифицирована в составе ОС).
* **Среда исполнения:** Axiom JDK Pro 17 (сертифицированный дистрибутив OpenJDK).
* **Криптография:** КриптоПро CSP 5.0 R2 и КриптоПро JCSP (Сертификаты ФСТЭК).
* **Веб-сервер:** Angie 1.12 (Сертификат ФСТЭК, замена Nginx).

**Ключевые механизмы защиты:**
* **Шифрование данных (At Rest):** Все файлы документов и персональные данные (ФИО, email, телефоны) в базе данных шифруются алгоритмом AES-256-GCM.
* **Изоляция ключей:** Ключи шифрования (`file.key`, `pii.key`) хранятся отдельно от БД и бэкапов, имеют права `600`.
* **Защита каналов (In Transit):** Строгий TLS 1.2/1.3 через Angie.
* **Аутентификация:** Клиенты входят по одноразовым magic-link (без паролей), администраторы — по УКЭП сертификатам с защитой от replay-атак (challenge-response).
* **Аудит:** Все действия (входы, подписи, удаления, бэкапы) фиксируются в неизменяемом журнале `audit_events`.

---

## Основные возможности

### Для клиентов
- Вход по одноразовой ссылке на email.
- Загрузка, просмотр и скачивание документов.
- Подписание УКЭП (CAdES-BES detached).
- Несколько подписей на один документ.

### Для администраторов
- Безопасный вход по УКЭП-сертификату.
- Управление клиентами и разделами (папками).
- **Визуализация подписей:** генерация PDF-копий, где в футере каждой страницы размещается логотип Банка и отметка о подписании, а на последней странице — синие штампы с данными сертификатов и доверенностей (ЭМЧД).
- Управление CRL (списками отзыва) и доверенностями.
- **Очистка дискового пространства:** безопасное удаление кэша Docker, старых логов, APT-кэша и файлов-сирот через веб-интерфейс.

## Развертывание в Production

### 1. Требования к серверу
* **ОС:** Astra Linux SE 1.8 или Debian 10+ (x86_64).
* **CPU:** 2 vCPU (минимум).
* **RAM:** 4 GB (минимум).
* **Диск:** 50 GB SSD.
* **Сеть:** Наличие внешнего IP, открытые порты 80 и 443 (для TLS).

### 2. Подготовка секретов (КРИТИЧНО)
До запуска необходимо сгенерировать ключи шифрования. Без них восстановление данных невозможно.
```bash
cd /opt/afinaz
mkdir -p secrets && chmod 700 secrets

# Генерация ключей
openssl rand -base64 32 > secrets/file.key
openssl rand -base64 32 > secrets/pii.key
openssl rand -base64 32 | tr -d '\n' > secrets/backup.pass

# Установка прав (UID 999 — это пользователь внутри контейнера)
chown -R 999:999 secrets
chmod 600 secrets/*.key secrets/backup.pass
```
*Сохраните эти три файла в защищенном месте (менеджер паролей, сейф).*

### 3. Настройка окружения (`.env.prod`)
Создайте файл `.env.prod` в корне проекта и заполните его:
```env
APP_DOMAIN=afina.nbdbank.ru
APP_BASE_URL=https://afina.nbdbank.ru
SECURE_COOKIES=true
ADMIN_IP_WHITELIST=10.0.0.0/8,192.168.0.0/16 # Подсети банка

DB_NAME=afina_db
DB_SUPERUSER_PASSWORD=<сложный_пароль>
DB_PASSWORD=<сложный_пароль>
DB_MIGRATOR_PASSWORD=<сложный_пароль>
DB_AUDITOR_PASSWORD=<сложный_пароль>

MAIL_MODE=smtp
MAIL_HOST=smtp.nbdbank.ru
MAIL_PORT=465
MAIL_USERNAME=noreply@nbdbank.ru
MAIL_PASSWORD=<пароль_от_почты>

CRYPTO_PRO_ENABLED=true
```

### 4. Подготовка файлов УЦ и КриптоПро
Положите в корень проекта:
* Дистрибутив `cryptopro-dist/linux-amd64_deb.tgz`.
* Корневые сертификаты УЦ в папку `certs/*.cer`.
* Файл `admins.env` (формат: `Иванов Иван Иванович|12345678901`).

### 5. Запуск
Убедитесь, что установлен Docker и Docker Compose. Затем выполните:
```bash
docker compose -f docker-compose-prod.yml --env-file .env.prod up -d --build
```

# Техническая документация (AfinaZ / ПАО «НБД-Банк»)

Документ предназначен для ИТ-специалистов, администраторов безопасности и DevOps-инженеров.

## 1. Архитектура и сертификация
Система спроектирована для работы в закрытом контуре банка.

### 1.1. Сертифицированные компоненты
| Компонент | Версия | Сертификат ФСТЭК | Назначение |
|---|---|---|---|
| Astra Linux SE | 1.8 | № 2557 | Базовая ОС (в контейнере и на хосте) |
| PostgreSQL | 15 | В составе Astra | Хранение данных, аудит PARSEC |
| Axiom JDK Pro | 17 | Сертифицирован | Среда исполнения (JVM) |
| КриптоПро CSP | 5.0 R2 | Сертифицирован | Криптография ГОСТ |
| Angie | 1.12.3 | Сертифицирован | Reverse-proxy, TLS-терминация |

### 1.2. Схема взаимодействия
1. **Клиент (Браузер + КриптоПро Плагин)** -> HTTPS -> **Angie** (TLS-терминация, защита от DDoS).
2. **Angie** -> HTTP -> **Spring Boot App** (проверка прав, логика).
3. **Spring Boot App** -> JDBC -> **PostgreSQL 15** (шифрование PII на уровне приложения).
4. **Spring Boot App** -> Локальное ФС -> **storage/documents/** (AES-256-GCM шифрование файлов).

## 2. Модель информационной безопасности
### 2.1. Управление ключами
* `file.key` — 32 байта (AES-256-GCM). Шифрует файлы документов.
* `pii.key` — 32 байта (AES-256-GCM). Шифрует email, телефоны и ФИО в БД.
* `backup.pass` — 32 байта. Используется утилитой `openssl` для создания бэкапов (AES-256-CBC).
* Ключи монтируются в контейнер `app` только на чтение (`:ro`).

### 2.2. Шифрование PII (Персональных данных)
Применяется JPA-конвертер `@Convert`. В БД хранятся зашифрованные блобы и хэши (SHA-256) для поиска.
* `users.email` -> `email_enc` + `email_hash` (unique).
* `users.phone` -> `phone_enc` + `phone_hash`.
* `users.full_name` -> Остается в plaintext для поиска по ФИО.

### 2.3. Проверка УКЭП (Криптография)
Отказались от слепой проверки через JCSP из-за проблем с корневыми сертификатами. Используется BouncyCastle:
1. Парсинг `CMSSignedData`.
2. Построение цепочки сертификатов (leaf -> intermediate -> root) вручную.
3. Проверка корня в `truststore` (папка `/app/certs`).
4. Проверка отзыва: поиск сертификата в CRL (папка `/app/crls`).
5. Проверка подписи (fallback на JCSP для ГОСТ 2012 при необходимости).

### 2.4. Разграничение доступа (RBAC)
* **afina_app:** только DML (SELECT, INSERT, UPDATE, DELETE). Не может удалить таблицы.
* **afina_migrator:** владелец схемы, используется Flyway.
* **afina_auditor:** только SELECT (для выгрузки аудита).

## 3. Развертывание (пошагово)
### 3.1. Структура директорий на сервере
```text
/opt/afinaz/
├── .env.prod                # Переменные окружения
├── docker-compose-prod.yml  # Манифест запуска
├── admins.env               # Список админов (CN|SNILS)
├── certs/                   # Корневые сертификаты УЦ (.cer)
├── crls/                    # Списки отзыва (скачиваются автоматически)
├── secrets/                 # file.key, pii.key, backup.pass (chmod 600)

├── backups/                 # Архивы БД и файлов (.enc)
└── logs/                    # Логи приложения (app.log)
```

### 3.2. Миграции БД (Flyway V1 - V21)
База данных разворачивается автоматически при старте контейнера.
* **V1-V14:** Базовая схема (users, documents, PII-шифрование, audit).
* **V15-V19:** Папки, доверенности (ЭМЧД), таблица визуализаций PDF.
* **V20-V21:** Настройки для сервиса очистки диска (CleanupService).

## 4. Обслуживание и мониторинг
### 4.1. Бэкапирование
Выполняется скриптом `backup-prod.sh` (вызывается по cron в 3:00).
* Дамп БД сжимается и шифруется (AES-256-CBC).
* Архив файлов `storage/` также шифруется.
* Ротация: удаление файлов старше 30 дней.

### 4.2. Очистка мусора (UI)
В админ-панели (`/admin/system`) доступна вкладка «Очистка мусора»:
* Удаление Docker build cache (безопасно, не трогает volumes).
* Очистка старых логов приложения и APT-кэша.
* Удаление файлов-сирот (файлы на диске, которых нет в БД).

### 4.3. Восстановление
Из-за политики безопасности пароль от бэкапа (`backup.pass`) не передается в UI. Восстановление зашифрованных бэкапов производится только через CLI:
```bash
./restore-prod.sh backups/afina_YYYYMMDD_HHMMSS.sql.gz.enc
```
